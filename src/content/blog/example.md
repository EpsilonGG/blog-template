这篇笔记是模板自带的**语法总览**。每一节都按同一个套路：先给一段**源码**（放在代码框里，可以整段复制走），紧接着给**渲染结果**，也就是它在页面上的真实样子。

写新文章时不用记住全部，把这页留在浏览器里对照着抄就行。下面所有写法都在本页真实渲染过一遍，不存在「文档说支持、实际不支持」的情况。

## 标题层级

正文用 `##` 起步，不要出现一级标题——文章标题已经由 frontmatter 的 `title` 渲染成 `<h1>`，正文里再来一个就重复了。

源码：

````markdown
## 二级标题（一节一个）

### 三级标题

#### 四级标题
````

渲染结果：

### 三级标题

#### 四级标题

再深就到 `#####`，但没有配套样式，会退回正文字号，所以不建议用。左侧目录栏只收前两级，标题写得浅一点读者才好扫。

## 段落、强调与行内代码

源码：

````markdown
这是一个普通段落。段落之间空一行，不要用两个空格强制换行。

**加粗**用来标出关键的人名、作品名或结论；`行内代码` 用来标出字段名、命令和文件名。

中文句子里的标点一律用全角，加粗标记要紧贴文字，别包住标点。
````

渲染结果：

这是一个普通段落。段落之间空一行，不要用两个空格强制换行。

**加粗**用来标出关键的人名、作品名或结论；`行内代码` 用来标出字段名、命令和文件名。

中文句子里的标点一律用全角，加粗标记要紧贴文字，别包住标点。

:::caution
加粗标记如果落在中文括号后面，CommonMark 会判定它不能收尾，于是把 `**` 原样印出来。写成「**名字**（罗马音）」而不是「**名字（罗马音）**」就不会出问题。`npm run check:prose` 就是专门抓这个的。
:::

## 链接

````markdown
[站内链接](/blog/) 会走客户端路由，[站外链接](https://astro.build/) 会在新标签页打开。
````

列表项里可以放多个段落，也可以放代码块——只要把内容缩进到列表项下面就行。

## 引用

引用块用来放**别人说的话**，或者需要单独成段、语气又比正文重一点的判断。它不应该被当成「重要提示」用，提示有专门的容器（见下一节）。

源码：

````markdown
> 引用块的第一段。
>
> 第二段要空一行，并在行首保留 `>`。
````

渲染结果：

> 引用块的第一段。
>
> 第二段要空一行，并在行首保留 `>`。

## 提示框

这是本站最特殊的一类语法：用 `:::` 围出一个容器，渲染成带标题的方框。认五种类型，标题自动取中文名：

| 类型 | 默认标题 |
| --- | --- |
| `note` | 说明 |
| `tip` | 技巧 |
| `important` | 要点 |
| `warning` | 注意 |
| `caution` | 警告 |

源码：

````markdown
:::note
默认标题是「说明」。
:::

:::tip[自定义标题]
方括号里的字会顶替默认标题。
:::

:::warning
需要读者停一下再看的内容放这里。
:::
````

渲染结果：

:::note
默认标题是「说明」。
:::

:::tip[自定义标题]
方括号里的字会顶替默认标题。
:::

:::warning
需要读者停一下再看的内容放这里。
:::

另外两种（`important` 与 `caution`）写法完全一样，只是默认标题分别是「要点」和「警告」。

:::note
写了一个不认识的类型名（比如 `:::danger`）不会报错，也不会丢内容——它会安静地退化成 `note`。宁可样式不对，也不让整段消失。
:::

:::important
容器内部可以放任何块级内容：段落、列表、代码块、表格都行。但**不要再嵌套一层容器**，嵌套的边框会挤在一起。
:::

## 代码块

围栏用三个反引号，语言名写在后面，构建时会做语法高亮，并且跟随页面的明暗主题切换配色。

源码：

````markdown
```python
def greet(name: str) -> str:
    """一个用来演示代码块样式的函数。"""
    return f"你好，{name}"
```
````

渲染结果：

```python
def greet(name: str) -> str:
    """一个用来演示代码块样式的函数。"""
    return f"你好，{name}"
```

很长的行不会撑破版式，而是在代码块内部横向滚动：

```bash
npm run build && npx astro preview --port 4321 --host 127.0.0.1 --strictPort --verbose --logLevel info
```

如果代码本身包含三个反引号（比如要演示 Markdown 源码），把外层围栏加长成四个反引号即可——本页所有「源码」框都是这么写的。

## 表格

源码：

````markdown
| 字段 | 类型 | 说明 |
| --- | :---: | --- |
| `title` | string | 文章标题，不能为空 |
| `pubDate` | date | 首次发布日期 |
| `tags` | string[] | 标签，必须是 `src/config/tags.json` 里的值 |
````

渲染结果：

| 字段 | 类型 | 说明 |
| --- | :---: | --- |
| `title` | string | 文章标题，不能为空 |
| `pubDate` | date | 首次发布日期 |
| `tags` | string[] | 标签，必须是 `src/config/tags.json` 里的值 |

第二行里的 `:---:` 是居中对齐，`---:` 是右对齐。表格列多的时候会被压缩，四列以内最舒服。

## 图片与图注

图片必须**独占一个段落**，`alt` 后面那对引号里的文字会变成图注（`<figcaption>`，可选中的真文本，不是伪元素）。图片放在 `public/images/blog/<文章 slug>/` 下，构建时会自动生成 WebP 与多尺寸变体。

源码：

````markdown
![示例图片](/images/blog/example/01.jpg "图注写在这里：它会被渲染成图片下方的小字")
````

渲染结果：

![示例图片](/images/blog/example/01.jpg "图注写在这里：它会被渲染成图片下方的小字")

连续两张**都带图注**的图片会自动并成一组，窄屏一行一张、宽屏并排：

![并排图 A](/images/blog/example/02.jpg "两张连续带图注的图会自动并成一组")

![并排图 B](/images/blog/example/03.jpg "窄屏一行一张，宽屏并排")

:::tip
图注就是 Markdown 里 `![alt](src "标题")` 的那个标题，不要手写 `<figure>` 标签。想让两张图并排，只要它们相邻、都带图注，不需要额外标记。
:::

## 注释（脚注）

正文里放一个上标，读者点一下会从底部弹出对应的注释。上标紧贴文字写，**不要**在它前面再加一层括号。

源码：

````markdown
正文里放一个上标，读者点一下会弹出注释[^1]。

[^1]: 这里是注释内容，可以写一两句话，也可以带[链接](https://astro.build/)。
````

渲染结果：

正文里放一个上标，读者点一下会弹出注释[^1]。

[^1]: 这里是注释内容，可以写一两句话，也可以带[链接](https://astro.build/)。

文末会自动生成一个「注释」小节，编号由出现顺序决定，不用自己数。同一个编号可以在一篇文章里被引用多次。

## 分割线

源码：

````markdown
---
````

渲染结果：

---

分割线只用来分隔**话题确实变了**的两段，同一篇文章里最好不超过两条。三个减号要单独占一行，上下各空一行，否则会被当成标题的下划线。

## 几个容易踩的坑

**成对的半角波浪线会变成删除线。** `~~这样~~` 在 Markdown 里是删除线，但日文副标题里的 `~` 如果敲成半角，两个波浪线之间的整段话就会被划掉。副标题一律用全角 `～`。`npm run check:prose` 会数博客页里 `<del>` 的个数，出现即报错。

**斜体在本站基本不用。** 中文没有斜体传统，屏幕上也不好看；需要强调就用加粗。

**标签是封闭集合。** frontmatter 里的 `tags` 只能取 `src/config/tags.json` 里列出的值，写别的会让构建直接失败——想加新标签先改那份 JSON。

**草稿不会上线。** frontmatter 里 `draft: true` 的文章不生成页面、不进首页、不进 RSS 与 sitemap。写一半的东西就这么放着。

**引用块和提示框不是一回事。** 引用块是「引用别人的话」，提示框是「我要提醒你一件事」。分不清的时候想一下：这段话是不是作者在补充说明？是的话用提示框。
